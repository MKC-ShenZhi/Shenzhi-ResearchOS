# Agent 部署前可用性调整

本次仅修改现有局部逻辑，没有执行测试、构建、Lint、类型检查、服务启动、数据库更新、提交、推送或部署。运行约定与操作命令见 [用户权益](../../../agent/entitlements.md#部署时的能力同步与资源默认值)。

## 调整内容

- 模型和工具身份移除全源码/锁文件绑定，保留稳定协议、参数及配置边界；离线导出顶层保留构建摘要。技能内容摘要和精确授权仍保留。
- 新正式 Policy 的 Grant/Permit/启动窗口从3600/60/10秒改为7200/120/30秒；旧签名不变。Worker租约45→90秒，暂时性心跳故障允许一个周期重试。
- 移除同用户任意未确认用量引起的全局调用阻塞；每次新调用仍预留并检查 used+held。持久化完成观察后，暂时性传输故障保留 spool/Outbox 和成本预留，不丢已产生的回答。
- 投递、未启动许可恢复、Grant关闭故障分别处理，避免单项网络失败阻塞后续恢复；提供仅重排暂时性 dead_letter 的显式命令。
- 输入预算保留原安全估算为默认，逐模型配置支持显式2字节/Token风险假设；不引入计数依赖，不改变每日额度与实际用量结算。未将启发式估算称为精确上界。
- 快速运行180→300秒、工具12→20次；其他模式900→1800秒、工具120→150次；Runtime默认36轮、Worker硬编码覆盖360轮，现统一为集中配置60轮。上下文压缩未变。
- 开发环境显式允许已批准、已分配测试Policy；生产默认拒绝。授权失败日志包含原因、调用标识及必要的版本差异，不记录请求正文或密钥。

## 首次升级与保留问题

- 旧授权仅存摘要，不能安全推断新版本等价：首次升级须导出、生成新发布包，经现有Admin发布/分配。以后普通实现更新不再要求重发能力授权。
- 没有改写历史Grant、Policy、用户分配或账本；旧任务应使用旧进程排空，随后切换新版本。未知用量、超额和未关闭Grant继续沿原恢复/对账路径处理。
- 新增预算JSON字段向后兼容默认1；切换到2有低估特殊文本的风险。旧代码不认识此字段，因此新包不得交给旧Backend发布；回滚先排空新任务，再切回旧进程与匹配的旧Policy，保留所有账本和验证公钥。
- 未自动续签、未重写状态机；跨上海自然日、授权过期、永久拒绝和无法确认的外部成本仍可能阻断。
- 优先由用户验证：三个模型普通聊天、工具调用、Research技能、并发额度、断网后结算恢复、心跳短暂失败、取消与撤销、重复start、任务关闭及旧Policy切换。特别观察预算选择2时的预留与实测差异。
