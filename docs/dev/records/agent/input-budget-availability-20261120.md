# 移除额外单次输入预算门槛

用户明确要求以总量控制为主，移除导致正常Agent任务失败的额外预算门槛。

只读实际失败记录：DeepSeek输入37309字节，旧Policy按1字节/Token加1024封装余量，输入估算38333；本地Policy上下文窗口32768，输出上限4096，Registry真实上下文未知。每日窗口仍有余额，失败原因是本地额外窗口，并非每日额度不足。该32768值由此前修复提供，不代表Provider真实上下文上限；Runtime默认180000字符上下文与此人为门槛也不匹配。

修改Backend的Entitlements.permit：不再用Policy.context_window_tokens裁切输入/输出预算。输入预留和输出上限继续在owner锁内受每日used+held约束；若Worker Registry明确声明真实上下文，则继续检查该声明。Registry未知时不编造模型上限，实际Provider仍可拒绝超长请求。历史Policy字段保留解析兼容，不改库、不重签、不需要重新导出能力或发布Policy。保留输出4096上限、每次调用预留、真实用量幂等结算及unknown成本持有。

额度不足明确返回QUOTA_EXHAUSTED；已声明的上下文不足返回MODEL_CONTEXT_WINDOW_EXCEEDED，并记录输入估算、可用额度及声明上下文。原始完整正文不进入诊断日志。以该失败请求为例，余额允许时预留上限为38333+4096=42429，完成后按实测结算并释放余量。

需要重启Backend，新一轮任务生效。未运行测试、构建、Lint或类型检查，未启动服务、修改数据库、提交或部署。既有失败任务未自动重跑；Provider实际长上下文行为未经本轮验证。
