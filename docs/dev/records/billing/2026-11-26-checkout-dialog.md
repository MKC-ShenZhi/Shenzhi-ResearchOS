# 订阅确认弹窗与支付宝跳转

## 本次变更

- 将套餐下方内嵌确认区替换为居中模态弹窗，套餐摘要、支付方式、提示和应付金额采用紧凑布局。
- 新订单仅选择支付宝；微信置后并标注暂未接入。历史微信待支付订单保留原渠道，引导回近期订单处理。
- 确认后通过现有 Billing Client 创建订单；已有待支付订单按原 ID 获取支付入口。live／pending／alipay 且具备跳转地址时在当前标签页跳转。
- Mock、已支付／已关闭及缺失支付入口均不自动跳转，提供订单恢复入口。打开／关闭弹窗不下单。
- 保留原有 Backend 购买约束、支付确认及权益履约逻辑，无后端或依赖变更。

## 验证

- 浏览器确认 3300 本地开发预览出现居中弹窗、遮罩与背景模糊，支付宝默认选中，微信禁选。
- Escape 关闭后焦点回到“续费套餐”；弹窗未再插入页面文档流。
- 新增组件行为测试覆盖仅确认时下单、支付宝默认渠道、旧订单 ID 复用、仅有效 live 支付结果跳转、历史微信恢复、滚动与焦点恢复、请求中关闭保护及 Tab 焦点循环。
- `pnpm typecheck`、本次组件与测试 ESLint、完整前端测试（460/460）、`pnpm build` 均通过。
- 浏览器验证 Shift+Tab 从关闭按钮回到支付按钮，Tab 从支付按钮回到关闭按钮，焦点保持在弹窗内。
- 不实际创建或支付订单；外部跳转分支使用测试替身验证，不宣称完成真实渠道支付验收。
