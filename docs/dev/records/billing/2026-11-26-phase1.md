## 实现范围

- 服务器控制的三档测试商品（CNY 整数分、30 天），订单快照、本人订单查询和支付入口恢复。
- 支付与履约分开持久化；支付成功后自动分配现有 Agent 权益；重复通知及并发续费幂等。
- 复用 Admin 的公共 Policy 分配、锁、审批校验、额度及审计；保留 ACTIVE_GRANTS_REQUIRE_DRAIN，支持 paid/pending 安全重试。
- 同套餐续期、到期实时拒绝新任务/Permit/Start，截止时间受订阅约束；已启动历史调用正常结算。
- 有效人工权益（含长期 Basic）不被自动购买覆盖；到期且未停用的人工权益允许接管。
- Subscription Tab 的中英文登录提示、当前权益/有效期、套餐购买、支付方式、二维码、支付宝链接、状态查询及重试。
- 显式 Mock 与生产隔离；支付宝官方 SDK 电脑网站支付/沙箱、查询/回调验签；微信官方 Go SDK Native/查询/通知验签解密。
- 独立 Payment 多阶段非 root 镜像、内部服务凭据、健康检查、Compose app/full profile 及环境准备工具。

## 实际 API、启动与配置

用户：`GET /api/v1/billing/plans`、`GET /subscription`、`GET/POST /orders`、`GET /orders/{id}`，
以及 `POST /orders/{id}/{payment,refresh,mock-pay}`，后缀均在 `/api/v1/billing` 下。
通知：`POST /api/v1/payment-webhooks/{alipay,wechat}`；公共 Web 入口 `/api/payment-notifications/{alipay,wechat}`。
Payment 内部：`GET /health`、`POST /internal/wechat/orders`、`GET /internal/wechat/orders/{id}`、`POST /internal/wechat/verify-notification`。

本地先 `uv sync --locked` 和 `uv run --env-file .env alembic upgrade head`，沿用现有启动命令。
Backend 开发环境显式配置 `ENVIRONMENT=development`、`BILLING_PAYMENT_MODE=mock`、`BILLING_MOCK_ENABLED=true`。
Admin 需先发布正式审批的 Policy。登录后 `/settings?tab=subscription` 购买并模拟付款，查询权益/有效期。
Docker 运行 `python infra/docker/prepare-env.py --from-local` 后沿用 app/full；新增 Payment 不发布宿主端口。

真实联调需支付宝 App/Seller、应用私钥/支付宝公钥文件、沙箱开关、HTTPS 通知/返回地址；
微信 App/Mch、商户 API 证书序列号/私钥文件、API v3 密钥、HTTPS 通知地址；
Backend/Payment 还需匹配独立内部凭据。全部变量名及权限说明见 [维护文档](../../../billing/README.md)。
