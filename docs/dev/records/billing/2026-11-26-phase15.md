## 修复结果

- P1-1：公共 `fulfill` 在权益事务前重新检查 Mock 运行模式、显式开关及 development/test 环境。refresh 与直接履约重试均覆盖；拒绝时保留 paid/pending 和错误原因。production 下真实支付宝签名通知仍正常完成履约。
- P1-2：核对实际安装的锁定 SDK `alipay-sdk-python==3.7.1467`：PagePay 动态 seller_id 不进入序列化结果，TradeQuery 响应模型没有可证明 App/seller 的身份字段。删除动态赋值；成功查询不生成支付事实，返回 `PAYMENT_QUERY_IDENTITY_UNVERIFIED`，等待已验签且核对实际 app_id/seller_id 的异步通知。没有增加猜测字段或自建验证协议。
- P1-3：复用 Admin advisory lock 和订单行锁，在创建事务内检查同一用户的 pending 及 paid/未完成履约订单，拒绝不同套餐并显示中英文业务提示。同套餐 checkout 复用原待支付订单及渠道；保留所有已支付订单。其他用户独立。

主要修改：Backend `services/billing/service.py`、`integrations/payment/alipay.py`，相关 Billing/Provider 测试，Web `subscription-panel.tsx` 提示，Billing 维护文档。

端到端另发现并最小修复共享契约缺口：Agent V2 返回 `schema_version: 1`，`TaskRunsResponseWire` 却拒绝该字段，造成浏览器读取回答失败。共享 wire 模型显式接受版本 1，保留其他版本/额外字段拒绝；更新 Backend/shared contract 定点测试及会话维护说明。没有修改 Agent 执行逻辑或放宽身份认证。

## 真实支付联调条件与限制

代码可进入支付宝沙箱及微信商户联调准备；当前缺少凭据，尚不能宣称已完成渠道联调或可正式收款。

- 支付宝：补齐 `ALIPAY_APP_ID`、`ALIPAY_SELLER_ID`、`ALIPAY_PRIVATE_KEY_FILE`、`ALIPAY_PUBLIC_KEY_FILE`；沙箱开关与商户产品权限匹配。查询不独立入账，必须验证通知可达、验签和 App/seller 匹配。
- 微信：补齐 `WECHAT_APP_ID`、`WECHAT_MCH_ID`、`WECHAT_CERT_SERIAL`、`WECHAT_PRIVATE_KEY_FILE`、`WECHAT_API_V3_KEY`、`WECHAT_NOTIFY_URL`，然后显式启用 `WECHAT_ENABLED=true`。当前平台证书自动下载模式需要对应商户配置。
- Backend/Payment 的独立服务 Token 已存在；商户身份两端需一致。运行中的 Payment 在未启用商户连接时健康。
- 公共 HTTPS 回调为 `/api/payment-notifications/alipay`、`/api/payment-notifications/wechat`，经专用 Web 路由保留原始请求体及必要签名 Header 转发 Backend；实际公网域名、TLS 和通知投递仍需联调确认。
- 凭据使用本地 env/安全文件及既有只读 secrets 挂载，路径和 env 已受 Git 忽略；不写入仓库。生产关闭 Mock，公共履约入口再次检查。
- 当前商品仍是 1/2/3 分测试价，正式收款前必须确认定价与产品权限。未扩展退款、对账、自动续费或其他 Phase 2 模块。

没有尚未修复的本轮 P1 或浏览器链路阻塞；真实商户凭据、HTTPS 路由及实际渠道投递验证待补齐。
