# 深知 ShenZhi 第一轮配色探索开发计划

日期：2026-10-13。当前交付为靛色和青绿两套视觉方向，靛色包含靛紫与靛蓝两个变体，共三份日夜 Theme。当前导入为 `indigo-research.css`，个人首选为青绿，最终方向待组内筛选与导师确认。

需求依据为用户提供的《11 - 关于深知 ShenZhi 视觉配色探索任务》内部协作稿 V0.1。可参考 alphaXiv 等科研产品的信息清晰度和阅读气质，保留深知书法标识与自己的品牌识别。

## 1. 开发目标与范围

本轮验证颜色体系与视觉气质，面向论文检索、阅读、文献管理和 AI 辅助研究。沿用 Next.js、React、TypeScript、Tailwind CSS 和现有主题机制。

配色范围包括页面背景、内容面板、浮层、边框、文字层级、主操作、链接、标签，以及悬停、选中和焦点颜色。页面信息架构、业务流程、主要布局、模块位置、组件结构、字体、字号、间距、圆角、文案、接口与数据沿用现有实现。

专业可信、信息清晰、长期阅读舒适和品牌辨识度是共同目标，不以高饱和、渐变或发光效果代替产品气质。

## 2. 候选方向与收敛理由

### 方案一 靛色

一句话定位：理性、清晰、克制，以靛色操作提示建立科研工具的专业秩序。

- 靛紫变体：`indigo-research.css`，日间主色 `#51478A`，夜间主色 `#B5ABE4`。
- 靛蓝变体：`warm-indigo.css`，日间主色 `#4F46E5`，夜间主色 `#A5B4FC`。
- 适用场景：发现、检索筛选、AI 对话、结构化研究报告。
- 选择理由：中性内容与靛色操作搭配，主要动作容易辨认；两种实现风格相近，合并为一套方向讨论。
- 优势：信息层级清楚，容易覆盖不同页面，日夜品牌一致。
- 风险：靛蓝容易与常见工具趋同，靛紫需要控制使用面积。

### 方案二 青绿

一句话定位：暖白与深灰承载科研内容，青绿集中于操作与状态，形成安静的阅读气质。

- 实现：`warm-teal.css`，日间背景 `#FBFAF4`，主色 `#1C7783`；夜间主色 `#7BD4D8`。
- 适用场景：论文浏览、文献管理、长摘要和 AI 报告阅读。
- 选择理由：个人偏好青绿，希望兼顾温和阅读感与专业工具气质。
- 优势：与靛色形成明确对照，品牌色集中于小面积交互，内容干扰较低。
- 风险：与成功状态颜色接近，需结合既有图标和文字区分；舒适度仍需真实使用反馈。

两套方向均使用中性文字和内容背景。夜间页面、侧栏、卡片、浮层分别为 `#151515`、`#1B1B1B`、`#222222`、`#2A2A2A`，同时保留各自色系的强调色。

## 3. Theme 组织与复现方式

颜色集中在 `apps/web/styles/themes/`：

- `indigo-research.css`
- `warm-indigo.css`
- `warm-teal.css`

每份配置提供相同的 44 个日间与 44 个夜间语义变量。`apps/web/styles/globals.css` 一次只导入一份候选，比较时替换唯一 Theme 导入。现有日间 / 夜间 / 跟随系统行为继续用于模式比较。

语义角色覆盖页面、侧栏、顶部栏、卡片、浮层、边框、标题、正文、辅助文字、主操作及前景、悬停、选中、文本选区、智能体和独立状态色。完整变量及使用方法见 [配色说明](./配色说明.md)。

背景与前景需配对，主要文字和操作文字以至少 4.5:1 为检查目标。成功、警告、错误独立表达，品牌色不承担所有状态含义。PDF 保留原始白纸，图片、图表和已有数据颜色保留信息含义。

## 4. 工作步骤与验收要求

### 第一步 观察与固定比较条件

熟悉现有页面和主题机制，观察背景、卡片、文字、按钮、标签和状态层级。固定视口、页面内容、检索词、筛选项、侧栏状态和滚动位置，形成可复现的比较条件。

### 第二步 明确目标并比较方向

围绕专业、可信、科研、理性和长期阅读讨论视觉目标，比较靛色与青绿。每套方向提供定位、选择理由、优势和风险，不以单组主色替代整套设计说明。

### 第三步 整理完整颜色变量

集中维护三份日夜 Theme，保持变量名一致。核对容器、文字、主操作、标签与状态的配对关系，确保替换单个导入即可整体比较。

### 第四步 检查颜色在页面中的分工

中性色承载正文、论文标题和大面积背景，品牌色用于主要操作、链接、当前导航及选中态。元信息保持可读层级，标签控制同时出现的彩色数量，AI 正文沿用内容面板配色。

### 第五步 应用到统一页面

统一覆盖以下三个代表页面：

1. 发现 / 搜索页 `/`：信息流、论文卡片、标签、输入与主要操作。
2. AI 助手页 `/agents?session=<有效会话ID>`：消息正文、引用、报告、输入与状态；不能将裸 `/agents` 重定向后的页面作为助手截图。
3. 知识库论文检索页 `/knowledge/search`：筛选、结果、次级信息与高密度阅读。

每份 Theme 在相同内容和状态下分别展示日间与夜间。现有数据不足时，使用浏览器内固定论文快照和明确标记的 AI 展示样例，不写入业务数据、不调用模型，并注明截图用途。

### 第六步 技术检查与视觉自检

运行现有类型检查、ESLint，以及 `node tests/visual/check-color-tokens.mjs`。核对正文、辅助信息、按钮、链接、导航、表单、菜单、弹窗和状态文字的颜色组合；检查截图实际页面、模式和主色是否正确。

颜色检查不代替真实页面体验。透明叠层、全部交互状态、移动端阅读和长期舒适度需进一步核验；不将不透明组合通过描述为全站无障碍认证。

### 第七步 整理组内评审材料

每套方向提交一句话定位、简短设计说明、完整 Theme、统一页面截图和检查记录。靛色保留两个变体，青绿单独展示，共三份实现 × 三个页面 × 日夜两种模式，即 18 张主要截图。截图与日志保存在项目外，Word 不随本次源码推送上传。

先进行组内横向比较，选择少量候选给导师确认大方向，再进入第二轮精修。

## 5. 当前验证结果与待处理事项

- 三份配置均提供完整的 44 个日间与 44 个夜间颜色，变量名一致。
- 共 336 组不透明文字与背景组合达到至少 4.5:1；靛紫最低约 4.82 / 5.71，靛蓝约 4.57 / 5.55，青绿约 4.54 / 5.33，依次为日间 / 夜间。
- TypeScript 检查与原有设置相关测试通过；ESLint 无错误，保留两条原有 Hook 依赖警告。
- 三个代表页面的日夜截图使用统一样本，已核对路径、模式和颜色。截图用于视觉比较，不作为实时推荐或模型生成验收证据。
- 原有 `/knowledge/topics` 页面缺少 Suspense 边界，阻止完整生产预渲染；该问题另行处理。
- 待完成：组内及导师评审、最终方向确认、第二轮精修、移动端与长期阅读体验检查。

## 6. 第一轮内部评审与希望达到的结果

评审不只判断“好不好看”，从以下维度讨论，不机械计算绝对分数：

- 专业可信感：是否符合科研知识工作产品定位。
- 科研产品气质：是否像可以长期使用的科研工具。
- 阅读舒适度：长时间浏览论文、列表、报告是否容易疲劳。
- 信息层级：主次内容和操作状态是否清晰。
- 品牌辨识度：是否有自己的视觉特点。
- 全站适配能力：是否能够稳定覆盖不同类型页面。

本轮希望得到具有明确设计理由、可以比较和继续迭代的视觉方向。青绿是个人首选，最终仍由组内筛选与导师确认；方向确定后进入第二轮精修与收敛。
