# 论文库会议、年份导航修复

调查日期：2026-10-23。功能与 API 范围见 [Paper Library V2](PAPER-LIBRARY-V2.md)。

## 现象与入口差异

直接打开 `/knowledge/search?mode=conference&conference=AAAI&year=2026`，等待
论文加载后点击其他年份或会议，可能出现 URL、当前会议、年份高亮和论文列表都
停留在原值。单标签页即可触发，多标签页不是必要条件。会议轮播等本地交互仍可工作。

调查中采用两种入口对照：

- 带参数直接进入：首屏地址包含 `AAAI&year=2026`，随后请求切换到 `2022`，
  复现路由缓存返回旧地址。
- 不带参数进入 `/knowledge/search`：相同缓存回退计算能保留之后请求的
  `AAAI&year=2022` 地址。

入口、预取与缓存建立顺序影响表现，因此不能以“打开几个标签页”作为稳定触发条件。

## 已确认的故障链一：静态路由缓存保留旧地址

在 Next.js **16.2.12** 中复现了静态页面首屏与客户端路由缓存的 canonical URL
不一致问题。线上首屏 HTML 的初始 Flight 数据、初始化脚本和导航缓存脚本也包含
相同数据与执行分支；结论不只依据独立 RSC 请求或本地构造的示例。
这证明了一条能造成无响应的路径，不代表所有间歇性故障都由同一原因造成。

具体链路如下：

1. 原 `app/knowledge/search/page.tsx` 可被静态预渲染。即使浏览器地址带有
   `mode/conference/year`，真实 HTML 内的初始 Flight 仍携带空 `q`（内部
   `renderedSearch`），页面段为不含查询参数的 `__PAGE__`。
2. Next 初始化状态时，从 `window.location` 获取 canonical URL，所以它包含
   当前地址的 `AAAI&year=2026`；同时根据空 `renderedSearch` 将该路由登记到
   无查询参数的缓存项。
3. `ConferenceBrowser` 点击处理通过 `router.push` 提交新地址。目标查询参数
   未直接命中缓存时，Next 的 `deprecated_requestOptimisticRouteCacheEntry`
   尝试复用无查询参数缓存。
4. 该分支优先保留缓存 canonical 中已有的查询参数。结果是请求地址为
   `AAAI&year=2022`，内部 `renderedSearch` 已变为 `2022`，返回的 canonical
   却仍为 `AAAI&year=2026`。
5. AppRouter 提供给 `useSearchParams` 的值来自 canonical URL。会议和年份
   高亮、`ConferencePapers` 的查询参数又来自 `useSearchParams`，因此仍显示
   原来的 `2026`，没有发起用户预期的新年份论文查询。

独立诊断使用真实 HTML 的路由树与初始查询元数据重跑初始化和缓存查询，得到上述
旧 canonical；将初始 `renderedSearch` 改为实际查询串后，不再命中该空参数回退项。
本记录不推断其他 Next.js 版本是否存在或已经修复同一问题；升级时仍需回归验证。

相关应用代码：

- `apps/web/app/knowledge/search/page.tsx`：页面渲染边界。
- `apps/web/features/knowledge/search/conferences/conference-browser.tsx`：读取 URL
  状态、提交会议/年份/分页导航及按参数查询论文。
- `apps/web/features/knowledge/search/conferences/conference-queries.ts`：会议元数据
  与会议论文使用独立查询 key。

## 已确认的故障链二：导航延迟期间旧年份覆盖会议选择

单独修复静态首屏缓存，仍不能解决所有短间隔点击问题。在只加入 `connection()`
的本地生产构建中，通过网关将 RSC 导航响应延迟 2 秒，完成以下受控复现：

1. 当前显示 `AAAI 2019`，点击 `ICML`。
2. 点击后约 269 毫秒，URL 和界面仍是 `AAAI 2019`，旧会议的年份按钮仍可点击。
3. 在第一次点击后约半秒内，再点击界面上的 `2022`。
4. 网关分别收到 `ICML 2025` 与 `AAAI 2022` 两条导航请求，均返回 HTTP 200，
   耗时约 2004 / 2003 毫秒；最终停留在 `AAAI 2022`。

原年份处理函数捕获了旧渲染中的 `selected`。第一次 `router.push` 等待导航提交时，
第二次点击仍用旧会议构建地址，于是较后的年份选择把会议切回 AAAI。该交互竞态在
请求均成功、没有 429 的受控环境中出现，不等同于第一条缓存故障，也不需要丢包。

这还说明只增加服务器超时时间不能修复旧状态组装请求的问题。修复必须让会议选择
及时写入 URL，并让后续年份、分页和规范化操作从事件执行时的当前 URL 读取条件。

## 与请求超时、丢包的区别

本次缓存计算可以在没有网络请求的诊断中返回错误地址，不需要超时或丢包参与。
线上抽样的文档和 RSC 请求均成功，未观察到 Cloudflare 将 HTML 与 RSC 内容混用；
抽样不能排除其他时间的网络故障，但不足以把本次现象归因于服务器时长保护。

排查同类问题时先看 URL 与选中状态：

- 点击后 URL 与高亮都保持原值：检查路由提交及 canonical 是否保留旧查询；
  此时新年份论文请求可能尚未产生。
- URL 与高亮已更新，但论文区持续加载或显示失败：检查
  `GET /api/v1/knowledge/papers` 的状态、耗时及 Request ID。后端上游默认
  30 秒超时，正式错误契约使用 `TIMEOUT`、`RATE_LIMITED`、
  `UPSTREAM_UNAVAILABLE` 等状态，详见 [知识底座接入说明](README.md)。
- RSC 导航请求持续 pending 也可能推迟路由提交，但它与本次已复现的缓存地址
  错误是不同机制，不能仅凭“点击无反应”认定两者相同。

短间隔点击需要分别验证路由连续提交、Query 请求取消、迟到响应及服务端错误。
线上抽样中，从无参数入口在约 0 / 63 / 104 毫秒连续点击 `2022 / 2021 / 2019`，
三次 URL 与选中年份都及时更新，最终显示 2019 年论文。另一组在约
0 / 298 / 581 毫秒点击 `2018 / 2017 / 2016`，前 862 毫秒仍显示旧年份，
随后最终正确显示 2016 年论文；两组均未观察到控制台错误。第二组属于暂时等待，
不能与长期保留旧 canonical 的缓存复现混为一谈，也不能据此认定线上发生了限流。
上述生产构建的延迟实验进一步确认了独立的旧状态竞态。

## 修复方式与边界

修复同时覆盖页面首屏与客户端参数提交两层。

在论文库页面入口调用并等待 `next/server` 的 `connection()`，将页面置于请求时
渲染边界，避免继续生成上述空查询的静态首屏种子。实际生产构建需要核对初始
Flight 是否携带当前查询串，不能只以开发服务中的点击结果判断修复完成。

会议模式新增 Feature 内的 `conference-navigation.ts`，会议、年份和分页使用
Next.js 支持的原生 History 集成更新 URL，让这些仅影响客户端论文查询的条件
不再等待 RSC 导航完成。处理后续事件时读取当前 URL，避免使用旧渲染捕获的会议
或年份：若旧年份按钮的值不属于新会议的实际年份，按新会议的可用年份规范化，
不将会议切回旧值。URL 规范化也重新读取当前地址，防止旧 effect 覆盖新的选择。

浏览器前进后退和既有搜索条件恢复继续使用 URL；跨页面导航与关键词检索沿用
现有路由边界。论文数据仍经 Knowledge Client → BFF → FastAPI 链路获取，
TanStack Query 的查询 key、新鲜期和取消规则继续使用原实现。数据请求仍可能
加载或失败，URL 的及时提交不表示论文已经返回。

该页面从静态预渲染改为请求时渲染，会增加页面请求的服务器渲染工作；不引入
新的业务 API、依赖、浏览器存储或全局缓存配置。后续若恢复静态渲染或升级 Next.js，
应先验证带查询参数直接进入的导航行为。
